## 1. Scope

This BRD covers the end-to-end user authentication and account-lifecycle flows for the Leasing Back Office (BO):

1. Super Admin creates a new user
2. New user first-time login (with temporary password)
3. User sets a permanent password
4. User login with expired password
5. Super Admin resets a user's password
6. User forgot password recovery path
7. Edit user
8. Session timeout / auto logout

Out of scope (this iteration): SSO, MFA, password recovery via email link, audit log UI.

## 2. Personas

| Persona | Description | Key actions |
|---|---|---|
| **Super Admin** | High-privilege BO operator who manages user accounts | Create user, Edit user, Reset password |
| **BO User** | Internal staff with Role-based access to BO modules | Login, set password, change password |

## 3. Business Rules

### 3.1 Temporary Password

- **R-TP-01** — Temporary password is generated by the system when:
  - Super Admin creates a new user
  - Super Admin clicks **Reset Password** for an existing user
- **R-TP-02** — Temporary password is delivered via email to the user's registered email address
- **R-TP-03** — Temporary password is valid for **7 days** from issuance
- **R-TP-04** — Temporary password is **single-use** — it expires after a successful login regardless of the 7-day window
- **R-TP-05** — If a user logs in with a temporary password, the system **must force** the user to set a new password before granting access to BO
- **R-TP-06** — If the temporary password has expired (7 days passed or already used), the user must contact the Super Admin to reset

### 3.2 Password Policy

- **R-PWD-01** — Password length: **8 – 20 characters**
- **R-PWD-02** — Must contain **at least one** of each:
  - Uppercase letter `[A-Z]`
  - Lowercase letter `[a-z]`
  - Digit `[0-9]`
  - Special character (allowed set below)
- **R-PWD-03** — Allowed special characters: `! @ # $ % ^ & * ( ) _ - + = [ ] { } ; : , . ? / \ |`
- **R-PWD-04** — New password **must not match** the temporary password (when setting from temp)
- **R-PWD-05** — New password **must not match** the user's most recent password (when resetting due to expiry)
- **R-PWD-06** — Password lifetime: **3 months** from the date of last change
- **R-PWD-07** — When a user enters a password that fails validation:
  - System shows an error message
  - System **does NOT lock** the user account
  - User may retry indefinitely (no lockout policy in this iteration)

### 3.3 Session Management

- **R-SES-01** — If no API requests are made within **8 hours**, the system **auto-logs out** the user
- **R-SES-02** — On logout (manual or auto), the system **must clear** all session data and tokens
- **R-SES-03** — After login, the system routes the user to the BO landing page corresponding to their Role

### 3.4 User Creation (Super Admin)

- **R-USR-01** — Fields required to create a user:
  - First name (Thai)
  - Last name (Thai)
  - Email
  - Role
  - Employee ID
  - Username
  - Status
- **R-USR-02** — Username and email must be **unique** within the system
- **R-USR-03** — On successful creation:
  - System generates a temporary password ([R-TP-01](#31-temporary-password))
  - System sends temporary password to the user's email
  - User appears in the User List with the chosen Status
- **R-USR-04** — If username or email is a duplicate, the system shows an error dialog and does not create the user

### 3.5 Forgot Password

- **R-FGT-01** — There is **no self-service password recovery** in this iteration
- **R-FGT-02** — User must contact a Super Admin who triggers **Reset Password** ([R-TP-01](#31-temporary-password))

## 4. User Stories

### Story US-01 — Super Admin creates a new user

**As a** Super Admin
**I want to** create a new BO user
**So that** they can access the Leasing Back Office with appropriate permissions

**Acceptance Criteria:**
- Form requires all fields listed in [R-USR-01](#34-user-creation-super-admin)
- Submitting valid, unique data shows a confirmation dialog before persisting
- On confirm: user is created, temporary password is generated, email is sent, user appears in the list
- Duplicate username or email triggers an error dialog and blocks creation
- Cancel returns the admin to the user list without creating

### Story US-02 — First-time login with temporary password

**As a** newly-created BO user
**I want to** log in using the temporary password from my email
**So that** I can set my own password and access BO

**Acceptance Criteria:**
- User enters Username + Temporary Password on the Login screen
- If credentials are wrong → error: "ชื่อผู้ใช้งานหรือรหัสผ่านไม่ถูกต้อง กรุณาลองใหม่อีกครั้ง"
- If temporary password has expired → error: "รหัสผ่านไม่ถูกต้อง หากลืมรหัสผ่าน กรุณาติดต่อผู้ดูแลระบบ"
- If valid and not expired → system redirects to New Password screen (forced)

### Story US-03 — Set new password from temporary password

**As a** user redirected from first-time login
**I want to** set a new password
**So that** I can continue using BO with my own credentials

**Acceptance Criteria:**
- Two fields: New Password, Confirm Password (both required)
- Validation against [R-PWD-01](#32-password-policy) – [R-PWD-04](#32-password-policy)
- If validation fails → error displayed inline
- If new password matches the temporary password → dialog: "Password ซ้ำ"
- On success → user is redirected to Login screen to log in with the new password
- After successful login with new password → system routes to BO landing per Role

### Story US-04 — Login with expired password

**As a** BO user whose 3-month password lifetime has elapsed
**I want to** be prompted to set a new password
**So that** I can continue accessing BO

**Acceptance Criteria:**
- User enters Username + Password on Login
- If invalid → standard error
- If valid but password expired → dialog: "Password expire" with action to set new password
- If user dismisses dialog → return to Login
- If user proceeds → New Password screen
- New password validation per [R-PWD-01](#32-password-policy) – [R-PWD-03](#32-password-policy), [R-PWD-05](#32-password-policy)
- If new password matches the most recent password → dialog: "Password ซ้ำ"
- On success → redirect to Login → login with new password → BO landing

### Story US-05 — Super Admin resets a user's password

**As a** Super Admin
**I want to** reset another user's password
**So that** the user can regain access after forgetting their password

**Acceptance Criteria:**
- From the User List or Edit User screen, the admin clicks **Reset Password**
- Confirm dialog explains the action
- On confirm → system generates a new temporary password ([R-TP-01](#31-temporary-password)) and emails the user
- Reset flow does **not** disclose the new password to the admin in the UI
- The user must then follow [US-02](#story-us-02--first-time-login-with-temporary-password) and [US-03](#story-us-03--set-new-password-from-temporary-password)

### Story US-06 — Auto-logout after inactivity

**As a** system
**I want to** terminate idle sessions
**So that** unattended BO sessions don't pose a security risk

**Acceptance Criteria:**
- No API call for 8 consecutive hours → auto-logout
- All client-side session data and tokens are cleared on logout
- User is redirected to Login screen
- Re-login is required to access any BO module
